# Contribution Guidelines

Ensure your pull request complies to the following guidelines:

- Start your topic and commits with a keyword like Add, Change, Remove or Bugfix.
- Don't use filenames in PR.
- Proof-read yourself.
- Please be nice.
- Be brave with contributing and commenting.
- Consider if the item you're adding to the list is actually pretty useful and/or exciting for the Nocode / Lowcode community or newcomers.
- In case we gather a lot of links that are kinda-useful, but not exactly awesome, we could create another list within the repo.

Thank you for your suggestions!

## Submission Requirements

This repository is a **curated collection of established, useful, and trustworthy No-Code and Low-Code tools**, not a directory for promoting newly launched products.

Before submitting a pull request, make sure your tool meets **all** of the following requirements:

- **Relevance:** The tool must have a clear and direct connection to No-Code or Low-Code development. General-purpose utilities, unrelated AI tools, and marketing services are not accepted.
- **Product maturity:** The tool must be publicly available, functional, and sufficiently mature for real-world use. Concepts, prototypes, waitlists, unfinished products, and early-stage experiments are not accepted.
- **Proven value:** The tool must offer meaningful functionality and practical value beyond a basic demo or landing page. Simply being new or AI-powered does not qualify.
- **Transparency:** The website must clearly identify the company or individual responsible for the product and provide accessible contact information.
- **Legal information:** Commercial services must provide appropriate legal information, including applicable terms of service, privacy policies, and company details. Anonymous or legally questionable services will not be accepted.
- **Quality:** The tool must have a professional, functional website with clear product descriptions and sufficient documentation or usage information.
- **No duplicates:** Check existing entries and open pull requests before submitting. Tools offering no meaningful distinction from existing entries may be rejected.
- **No advertising:** Purely promotional submissions, affiliate links, SEO-driven contributions, and mass-submitted product listings are not accepted. Contributors must disclose any affiliation with the submitted product.

### Pull Request Requirements

Every pull request must:

- Explain **why the tool deserves to be included** and what makes it useful to the No-Code / Low-Code community.
- Provide a working link to the official website or repository.
- Confirm that the tool meets the submission requirements above.
- Follow the existing list structure and formatting conventions.
- Avoid unrelated changes.

### ⚠️ Important Notice

**Pull requests that do not comply with these contribution guidelines will be closed without comment or further explanation.**

Inclusion in this list is at the maintainers' discretion. Meeting the requirements does not guarantee acceptance. We reserve the right to reject submissions that do not meet our standards for relevance, maturity, quality, or trustworthiness.

Please review these guidelines carefully **before opening a pull request**.

## Updating your PR

A lot of times, making a PR adhere to the standards above can be difficult.
If the maintainers notice anything that we'd like changed, we'll ask you to
edit your PR before we merge it. There's no need to open a new PR, just edit
the existing one. If you're not sure how to do that,
[here is a guide](https://github.com/RichardLitt/knowledge/blob/master/github/amending-a-commit-guide.md)
on the different ways you can update your PR so that we can merge it.
